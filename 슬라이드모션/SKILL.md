# 슬라이드모션 — 실측된 모핑을 슬라이드에 넣는다

## 철칙 4개 (어기면 다 갈아엎게 된다)

1. **모션은 예쁨이 아니라 관계 구조에서 나온다.**
   먼저 콘텐츠의 관계(순서 / 병렬 / 포함)를 읽는다. 관계가 없으면 모션도 없다 —
   **모션을 얹지 말고 내용을 먼저 고친다.**
2. **수치는 실측이다. 지어내지 마라.**
   아래 카탈로그의 숫자는 실제 영상을 프레임 단위로 잰 값이다.
   「부드럽게」「자연스럽게」 같은 형용사로 바꾸지 마라 —
   **미지정 칸은 모델이 기본값(`0.3s ease`)으로 채우고, 그러면 원본이 안 나온다.**
3. **모션을 고르는 건 사람이다.** 후보 2~3개를 제시하고 **멈춘다**(게이트 ①).
   혼자 정하고 만들어 버리지 않는다.
4. **열었을 때 아무것도 저절로 움직이지 않는다.**
   발표용 슬라이드다. 발표자가 말을 마친 뒤에 넘어가야 한다.

> **실측 ≠ 취향.** 카탈로그는 "원본이 어떻게 움직이는가"이지 "무엇이 좋은가"가 아니다.
> 사용자가 실측과 다른 걸 원하면 **그건 틀린 게 아니라 연출 선택**이다.
> 다만 **바꾼 값은 「연출」이라고 말해 준다.** 둘을 섞으면 나중에 무엇이 근거인지 알 수 없다.

## 워크플로우

```
0. 슬라이드 내용 받기
      ↓
1. 관계 구조 판별          ← 이 스킬의 심장
      ↓
   관계가 없다 ──▶ 3. 내용 재구성 제안 ──▶ ★게이트②(사람이 승인)
      ↓ 관계가 있다
2. 후보 2~3개 제시 ──────▶ ★게이트①(사람이 고른다)
      ↓
4. 구현 — 고른 패턴의 「모션 스펙 + 구현 규칙」 + 5절 공통 규격을 그대로 적용
      ↓
5. 각 패턴의 「확인」 목록으로 자가 점검 → 7절 수정 루프
```

**게이트에서는 반드시 멈춘다.** 후보를 제시하고 바로 만들기 시작하지 않는다.

**4단계에서 카탈로그의 수치를 요약하거나 반올림하지 마라.** 적힌 값을 그대로 코드에 넣고,
파일 맨 위 주석에 출처(실측/추정/빌림)를 밝힌다.

## 1. 관계 구조 판별 (심장)

슬라이드 내용을 보고 **항목들이 서로 어떤 관계인지** 먼저 정한다.

| 관계 | 신호 | 원시동작 | 슬라이드 예 |
|---|---|---|---|
| **순서** — 같은 형식이 차례로 | 연도·번호·단계가 있다 | **① 창 + 스트립** | 연표, 로드맵, 카운트 |
| **병렬 중 하나 강조** — 동급 N개 | 항목이 대등하고 N개다 | **② 요소 A→B** | 인물 소개, 요금제, 메뉴판, 사례 모음 |
| **포함** — 전체 ↔ 부분 | 안으로 들어가거나 밖으로 나온다 | **③ 카메라** | 지도, 조직도, 목업, 다이어그램 |

> **원시동작과 패턴을 헷갈리지 마라.** ①은 「창 + 스트립」이라는 **메커니즘**이고,
> 카탈로그의 「년도 오도미터」는 그 **숫자 사례**다. 숫자가 아니어도 —
> 단계 이름·월·챕터 제목이어도 — **같은 메커니즘(창 안에서 스트립을 밀어 올린다)을 쓴다.**
> 다만 `(target - cur + 10) % 10` 같은 **0~9 순환 규칙은 숫자일 때만** 적용된다.
> 숫자가 아니면 항목을 순서대로 쌓고 인덱스만큼 밀면 된다.

### 판별 질문 셋

1. **항목의 개수가 정해져 있고 순서가 의미를 갖는가** → 순서 (①)
2. **항목들이 대등한가, 그리고 한 번에 하나만 보면 되는가** → 병렬 (②)
3. **한 항목 안으로 들어가거나 전체에서 부분으로 좁히는가** → 포함 (③)

### 관계가 안 보일 때 — 불릿 목록이라면

**불릿 목록에는 모션을 넣을 자리가 없다.** 불릿은 관계가 아니라 나열이기 때문이다.
이때 할 일은 모션을 얹는 게 아니라 **내용을 셋 중 하나로 다시 쓰는 것**이다.

- 항목에 시간·단계가 숨어 있다 → **순서**로 다시 쓴다 (①)
- 항목이 대등한 선택지다 → **병렬**로 다시 쓴다 (②)
- 큰 개념 하나와 그 안의 세부다 → **포함**으로 다시 쓴다 (③)

재구성안을 **글로 먼저 보여주고 승인을 받는다** (게이트 ②). 내용이 바뀌는 일이므로
모션보다 훨씬 중요한 결정이다.

---

## 2. 후보 제시 → ★게이트 ①

관계를 정했으면 **그 관계에 맞는 패턴 2~3개**를 아래 카탈로그에서 골라 제시한다.

각 후보에 대해 이 셋만 말한다 — 길게 쓰지 않는다.

- **무엇이 움직이나** (한 문장)
- **어떤 인상을 주나** (한 문장)
- **이 슬라이드에 맞는 이유**

그리고 **멈춘다.** "어느 쪽으로 할까요?" 로 끝낸다.

> ⚠️ **「사진이 쏙」은 먼저 추천하지 않는다.** 실측이 없고 재현에 실패한 패턴이다
> (아래 카탈로그 5번 참조). 사용자가 그 연출을 명시적으로 원할 때만 쓴다.

## 3. 공통 상수 — 모든 패턴에 적용

### 이징

```
cubic-bezier(0.25, 0.1, 0.35, 0.95)
```

**오도미터 22점 + 하이라이팅 51점 = 합동 73점 최소제곱 피팅.** 두 패턴에 하나의 공통
곡선이 성립했다 (각자 단독 최적과의 차이가 오차 범위).

| 곡선 | RMSE (합산) | |
|---|---|---|
| **★ 공통 최적** | **0.0330** | 채택 |
| `ease` | 0.0635 | reveal.js 기본값 |
| `ease-out` | 0.0563 | |
| `ease-in-out` | 0.1668 | **최악** |
| `linear` | 0.1647 | 최악 |

> ★ **`ease-in-out` 과 `linear` 는 쓰지 마라.** 두 패턴 모두에서 가장 안 맞았다.
> "모핑은 부드럽게 시작해 부드럽게 끝난다"는 통념이 실측과 정반대다.
> 실제로는 **거의 곧바로 최고속에 올라가 길게 감속한다.**

### 전환 시간에는 공통 상수가 없다

**0.30 / 0.37 / 0.71 / 0.96초** — 패턴마다 다르다. **움직이는 거리가 멀수록 길다.**
「모핑은 0.5초」 같은 값을 쓰지 마라.

> ★ **눈으로 잰 시간은 물리 시간보다 짧다.** 위 곡선은 전체의 **69% 지점에서 이미
> 진행률 90%** 를 지난다 — 그때 「도착했다」고 보인다. 남은 10% 가 나머지 31% 시간에
> 걸쳐 천천히 안착한다. **그 안착이 무게감을 만든다. 길어 보인다고 줄이지 마라.**

## 4. 카탈로그 — 원시동작 3종 · 패턴 5개

각 패턴은 **모션 스펙(실측) / 구현 규칙(직접 만들어 확인) / 확인 목록** 으로 되어 있다.
**「구현 규칙」에 적힌 것은 전부 실제로 밟아 본 함정이다.** 임의로 빼지 마라.

---

### ① 년도 오도미터 — 원시동작 ① 창 + 스트립

> **관계: 순서.** 연표·로드맵·카운트. 근거: 22점 실측 (2026-07-28)

숫자 4자리가 세로 스트립으로 굴러가고, 이미지와 캡션이 함께 교대한다.

**모션 스펙**

- 숫자 롤 **960ms**, 공통 이징
- 나가는 이미지 **480ms**, 공통 이징 — 같은 순간 출발, **먼저 끝난다**
- 캡션 페이드 **~260ms** (추정값 — 프레임 피팅 안 함)
- 유지(정지) **750ms**. 셋은 **같은 순간에 출발하고 따로 도착한다**

**구현 규칙**

- 각 자리는 **폭 px 고정 + `overflow:hidden` 창**. 창 안 스트립을 `translate3d` 로만 이동
- ★ **항상 앞으로만 굴린다. 최단거리 금지** — `(target - cur + 10) % 10`.
  9→0 은 앞으로 1칸, 8→4 는 앞으로 6칸이다
- ★ **네 자리가 동시 출발·동시 도착. 스태거 금지.** 이동 거리만 달라서 속도가 달라 보이는데,
  **이 효과의 인상 전체가 여기서 나온다**
- ★ **들어오는 이미지는 움직이지 않는다.** 밑에 깔려 있고 드러날 뿐이다.
  크로스페이드도 슬라이드인도 아니다. **나가는 한 장만** 왼쪽으로 민다
- 자릿수에 `font-variant-numeric: tabular-nums`
- 스트립은 0~9 를 10주기 이상 쌓아두고, 끝에 닿기 전에 **같은 숫자가 보이는 앞쪽
  사이클로 소리 없이 되감는다.** 되감을 때는 `transition:none` + 강제 리플로우

**확인**: 자리마다 속도가 달라 보이는가 / 들어오는 이미지가 가만히 있는가 /
이미지가 숫자보다 먼저 끝나는가 / 되감기가 매끄러운가

### ② 하이라이팅 승격 — 원시동작 ② 요소 A→B

> **관계: 병렬 중 하나 강조.** 인물 소개·요금제·옵션 3안. 근거: **51점 실측** (가장 강한 측정)

한 줄에 놓인 카드 3장 중 하나가 넓어지고 나머지가 좁아진다. 가로 아코디언.

**모션 스펙**

- 전환 **380ms** (실측 367~400ms, 5회 전부 일치), 공통 이징
- ★ **카드끼리 직접 넘어가지 않는다. 반드시 균등 상태를 거친다**

  ```
  강조 ──380ms──▶ 균등 ──450ms 유지──▶ 다음 강조 ──1200ms 유지──▶ …
  ```

- 기하 (1920 기준): 강조 폭 **1119px** / 축소 **281px** / 균등 **512px**
- 간격은 균등 **105px** → 강조 **33px**. **폭만 바꾸지 말고 간격도 같이 줄인다**
- 높이 강조 **773px** / 축소 **427px**, **바닥 정렬**
- 강조된 카드에만 본문이 페이드인 (240ms, 120ms 지연)

**구현 규칙**

- 폭 변화는 **`grid-template-columns` 전환**으로. `gap` 도 같이 전환한다
- ★★ **트랙을 `fr` 로 쓰지 마라. 반드시 px 로 못 박아라.**
  `fr` 은 트랙 합에 대한 비율이라, 합이 같이 변하면 같은 이징을 걸어도 픽셀 폭의
  진행이 빨라진다 (t=0.1 에서 0.072 여야 하는데 **0.119** 가 된다)
- 개별 카드에 `width` 를 transition 하지 마라. `scaleX` 로 흉내내지도 마라 — 글자가 납작해진다
- 상태는 부모의 커스텀 속성으로만 표현하고, 자식은 상태를 모르게 한다

**확인**: 균등을 거치는가 / 간격이 같이 줄어드는가 / 트랙이 px 인가

### ③ 그리드 → 히어로 — 원시동작 ② (2차원)

> **관계: 병렬 중 하나 강조** (항목이 많고 격자일 때). 근거: 프레임 차분 실측

격자에 놓인 항목 하나가 **제자리에서** 슬라이드 전체로 커진다.

**모션 스펙**

- 그리드 → 히어로 **300ms** (9프레임), 공통 이징
- 그리드 안에서 큰 자리 ↔ 작은 자리 교환 **367ms** (11프레임)
- 기하 (1920×1080): 카드 영역 `x70 y141 w1790 h873` /
  큰 카드 `w850 h873` / 작은 카드 `w430 h426`, 열 x = 944·1408, 행 y = 141·588,
  간격 가로 34 · 세로 21
- 나머지 카드는 **자리를 옮기지 않고 있던 자리에서** 페이드아웃 (200ms)

**구현 규칙**

- ★★ **CSS Grid 로 짜지 마라.** `grid-column` / `grid-area` 는 **애니메이션되지 않는다**
  (`getAnimations()` 가 0을 돌려준다 → 전환 없이 그냥 점프한다). **이 패턴의 결정적 함정**
- ★ **`position:absolute` + `left/top/width/height` 를 px 로 전환**한다.
  절대 위치라 형제에게 리플로우가 전파되지 않는다
- **`transform: scale()` 로 키우지 마라** — 안의 글자·사진이 찌그러진다
- 카드 안 글자는 `font-size` 전환으로 키워도 된다 (절대 위치 요소 내부라 안전)

**확인**: 툭 튀지 않고 부드럽게 커지는가 (튀면 Grid 로 짠 것) / 제자리에서 커지는가 /
글자가 안 찌그러지는가

---

### ④ 목업 줌스루 — 원시동작 ③ 카메라

> **관계: 포함(전체↔부분).** 목업·지도·다이어그램. 근거: 프레임별 각도·면적 추적

기기 목업이 확대·회전하며 화면 밖으로 빠져나가고, 뒤에 깔려 있던 다음 장이 드러난다.

**모션 스펙**

- 전환 **709ms** (17프레임)
- ★ **회전은 단일 각도 + easing 으로 만들지 마라.** 궤적이 **가속형**이라 공통 이징(감속)과
  반대다. 아래 키프레임을 그대로 재생한다 (음수 = 반시계)

  ```
  0.000:    0°     0.059:  -1.6°    0.118:  -7.6°    0.176: -19.8°
  0.235: -51.1°    0.294: -58.2°    0.353: -63.2°    0.412: -67.3°
  0.471: -77.9°    0.529: -86.5°    0.588:-107.8°    0.647:-112.5°
  0.706:-122.0°    1.000:-140.0°   ← 마지막만 외삽
  ```

- 배율 키프레임: `0: 1.00 / .059: 1.10 / .118: 1.29 / .176: 1.37 / 1.0: 5.00`(외삽)
- 회전과 배율을 **하나의 transform 키프레임**으로 합치고 `easing` 은 `linear`
  (리듬이 이미 키프레임에 들어 있다)
- 목업 위 텍스트는 **페이드아웃**: `0 불투명 → 0.176 불투명 → 0.294 투명`
- ★ **다음 장은 확대되지 않는다.** 처음부터 최종 크기로 뒤에 깔려 있다

**구현 규칙**

- ★★ **`transform-origin` = 들어갈 지점(목업 화면의 중심 좌표).**
  슬라이드 중앙에 두면 목업이 옆으로 흘러 나가 전혀 다른 연출이 된다.
  **검증법: 제대로 잡혔으면 전환 내내 목업의 중심 좌표가 움직이지 않는다**
- ★ 목업을 키우지 말고 **목업을 담은 레이어에 transform 을 건다**
- ★ CSS transition 이 아니라 **Web Animations(`element.animate()`) 키프레임**으로 간다.
  transition 은 시작·끝 두 점을 하나의 이징으로만 잇는다
- ★ **목업 화면의 배경색 = 다음 장의 배경색.** 중간에 목업 화면이 슬라이드를 덮는데
  색이 다르면 커다란 색면이 지나가는 게 보인다
- ★ 앞뒤 장의 내용을 **이으려 하지 마라.** 원본도 완전히 다른 내용이었다

**확인**: 중간(t≈0.5)에 목업이 거의 가로로 누워 있는가 / 제자리에서 커지는가 /
큰 글자가 화면을 덮지 않는가 / 커다란 색면이 지나가지 않는가

---

### ⑤ 사진이 쏙 — 원시동작 ② (크기+위치) · ⚠️ 근거 약함

> **⚠️ 이 패턴만 실측이 없다.** 원본 완성본이 **물리 모니터를 카메라로 찍은 화면**이라
> 프레임 실측이 원천적으로 불가능했다. 시간·이징을 다른 패턴에서 **빌려 썼고,
> 재현 결과는 실패로 판정됐다.** 먼저 추천하지 말고, 사용자가 명시적으로 원할 때만 쓴다.

로고와 사진이 **서로 반대 방향으로 교차한다** — 하나는 작아지며 물러나고 하나는 커지며 들어온다.

**스펙** (기하 = 편집 화면 판독값, 오차 있음 / 시간·이징 = **빌린 값**)

- 슬라이드 1: 로고 `290×290 @(860,380)` · 사진 `250×340 @(-60,640)`
- 슬라이드 2: 로고 `140×140 @(1644,92)` · 사진 `680×930 @(620,250)`
- 전환 500ms(빌림), 공통 이징(빌림). 둘은 **같은 순간 출발·도착**

**구현 규칙**

- 메커니즘은 ③과 같다 — `position:absolute` + `left/top/width/height` px 전환
- ★★ **시작 상자와 끝 상자의 가로세로 비를 같게 맞춰라.**
  `width` 와 `height` 를 따로 보간하므로 비가 다르면 **중간에 찌그러진다**
  (비 0.735 → 1.800 이면 t=0.25 에 이미 1.192). 위 좌표는 0.735 → 0.731 로 맞춰 뒀다

**확인**: 전환 중간에 사진이 찌그러지지 않는가

## 5. 공통 규격 — 어떤 패턴이든 이대로 만든다

```
- 1920×1080 고정 무대 + transform: scale() 로 화면에 맞춤 (레터박스).
  브라우저 확대 100% 에서도 잘리지 않아야 하고, 창 크기 변화에 실시간 대응한다
  (ResizeObserver 로 갱신)
- 단일 HTML 파일. 외부 의존은 웹폰트까지만
- ★ 조작은 사람이 한다. 클릭 / ← → / Space / Esc 로만 움직인다
  - 페이지를 열었을 때 아무것도 저절로 움직이지 않는다. 첫 화면은 정지 상태다
  - 타이머로 자동 전환하는 코드를 넣지 마라 (setInterval·연쇄 setTimeout 금지)
  - 자동재생을 굳이 넣겠다면 기본값은 꺼짐이고, 사람이 켜야만 돈다
- 전환 중에는 입력을 무시한다 (연타로 상태가 꼬인다)
- 상태는 절대 인덱스로 들고 양방향으로 설계한다 (뒤로 가기가 꼬이기 쉽다)
- prefers-reduced-motion: reduce 대응 (전 duration 0)
- 모션 상수는 파일 맨 위에 모으고, 출처(실측/추정/빌림)를 주석으로 밝힌다
```

### 디자인은 사용자 것이다 — 레퍼런스를 흉내내지 않는다

카탈로그가 주는 것은 **좌표와 시간뿐**이다. 색·글꼴·주제는 하나도 지정하지 않았다.

- 주제·카피·사진·타이포·색은 **전부 새로 고른다**. 정한 이유를 주석 한 줄씩 남긴다
- **이미지는 플레이스홀더로 두지 말고 실제 사진을 골라 채운다** (Unsplash 등)
- 폰트는 **역할 3종으로 나눠서** 고른다 — (가) 큰 숫자/헤드라인 (나) 국문 본문 (다) 모노 라벨

## 6. 함정 — 카탈로그 전체에 적용

- ★★ **「2단계 커밋」 — transition 을 붙이는 것과 값을 바꾸는 것을 같은 프레임에 하지 마라.**
  스타일이 플러시되지 않아 **전환이 아예 안 걸리고 요소가 순간이동한다**
  (`getAnimations()` 가 0을 돌려준다).
  → transition 을 붙인 뒤 **강제 리플로우(`el.offsetHeight`)** 하거나
    **`requestAnimationFrame` 으로 다음 프레임에** 값을 바꾼다.
  ★ 이게 **「동시 출발」을 조용히 깨뜨린다** — 한쪽은 굴러가는데 다른 쪽만 텔레포트하는데,
  눈으로는 "빠르네" 정도로 보여 놓치기 쉽다
- ★ **기능 이름만 적으면 기본값은 모델이 정한다.** "자동재생 토글" 이라고만 적으면
  토글을 만들고 **기본값을 켜 둔다.** 원하는 기본 상태는 **문장으로** 적는다
- ★ **"부드럽게"는 지시가 아니다.** **대상 / A→B / 시간 / 이징 / 순서 다섯 칸을
  다 채워야** 재현된다. 빈 칸은 `0.3s ease` 로 채워진다
- ★ **모핑되는 요소는 슬라이드를 나누지 않는다.** 같은 DOM 노드를 유지하고 상태만 교체한다.
  나누는 순간 PPT 와 똑같은 요소 매칭 문제가 생긴다
- ★ **`var()` 에서 파생된 속성은 그 속성에도 transition 을 따로 걸어야 한다.**
  `font-size: calc(var(--w)*.55)` 를 써 두고 `--w` 만 바꾸면 폭은 부드럽고 글자는 툭 점프한다.
  등록되지 않은 커스텀 속성은 그 자체가 보간되지 않는다
- **`transform`·`opacity` 가 기본이다.** 단, **조건부 규칙**이다 —
  레이아웃 자체가 변하는 효과에는 `grid-template-columns`(②) 나
  절대 위치 px 전환(③④⑤)이 정답이다. `font-size` 전환도 **절대 위치 요소 내부라면 안전**하다
- **PDF·이미지로 내보내면 모션은 전멸한다.** 배포본은 정지 상태 기준으로 따로 설계한다
- **모핑 남용 금지.** 도입부 1회 + 핵심 전환 1~2회가 상한선이다

## 7. 수정 루프 — 증상에서 원인으로

| 증상 | 원인 | 고칠 곳 |
|---|---|---|
| 열자마자 저절로 움직인다 | 타이머가 들어갔다 | 공통 규격 (기본 상태) |
| 툭 튀고 전환이 없다 | Grid 애니메이션 불가 / 플러시 누락 | ③ 구현 규칙 · 2단계 커밋 |
| 한쪽만 순간이동한다 | **2단계 커밋 누락** | 함정 1번 |
| 글자가 납작해졌다 | `scaleX` 로 폭을 흉내냈다 | ② 구현 규칙 |
| 안의 내용이 찌그러진다 | `transform: scale` 로 키웠다 / 상자 비가 다르다 | ③⑤ 구현 규칙 |
| 글자만 툭 점프한다 | `var()` 파생 속성에 transition 안 걸었다 | 함정 5번 |
| 대상이 옆으로 흘러 나간다 | `transform-origin` 이 슬라이드 중앙 | ④ 구현 규칙 |
| 이징이 미묘하게 어긋난다 | 트랙이 `fr` 이다 | ② 구현 규칙 |
| 되감기에서 숫자가 거꾸로 흐른다 | 리셋에 `transition:none` 이 없다 | ① 구현 규칙 |
| 레퍼런스랑 똑같이 생겼다 | 디자인 자유 영역을 안 열었다 | 5절 |

**증상이 표에 없으면 추측하지 말고 사용자에게 무엇이 어떻게 보이는지 되묻는다.**
