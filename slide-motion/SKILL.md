# 슬라이드모션 — 실측된 모핑을 슬라이드에 넣는다

## 철칙 4개 (어기면 다 갈아엎게 된다)

1. **모션은 예쁨이 아니라 관계 구조에서 나온다.**
   먼저 콘텐츠의 관계(순서 / 병렬 / 포함)를 읽는다. 관계가 없으면 모션도 없다 —
   **모션을 얹지 말고 내용을 먼저 고친다.**
2. **수치는 실측이다. 지어내지 마라.**
   「부드럽게」 같은 형용사로 바꾸지 마라 — **미지정 칸은 모델이 기본값(`0.3s ease`)으로
   채우고, 그러면 원본이 안 나온다.** 값을 요약하거나 반올림하지도 마라.
   ★ **값을 모르면 임의로 정하지 말고 멈춘다.** 패턴 문서를 못 읽는 상황이면 §4.1 로 간다.
3. **모션을 고르는 건 사람이다.** 후보 2~3개를 제시하고 **멈춘다**(게이트 ①).
4. **열었을 때 아무것도 저절로 움직이지 않는다.** 발표용 슬라이드다.

> **실측 ≠ 취향.** 카탈로그는 "원본이 어떻게 움직이는가"이지 "무엇이 좋은가"가 아니다.
> 사용자가 실측과 다른 걸 원하면 **틀린 게 아니라 연출 선택**이다.
> 다만 **바꾼 값은 「연출」이라고 말해 준다.** 섞으면 무엇이 근거인지 알 수 없게 된다.

## 워크플로우

```
0. 슬라이드 내용 받기 · 어디에 들어가는지 확인(새 장인가 기존 덱인가 → §5.1)
      ↓
1. 관계 구조 판별          ← 이 스킬의 심장
      ↓
   관계가 없다 ──▶ 내용 재구성 제안 ──▶ ★게이트②(사람이 승인)
      ↓ 관계가 있다
2. 후보 2~3개 제시 ──────▶ ★게이트①(사람이 고른다)
      ↓
3. 해당 패턴 문서를 읽고 그대로 구현 (아래 카탈로그의 references/…)
      ↓
   문서를 못 읽는다 ──▶ ★§4.1 (값을 지어내지 말고 요청한다)
      ↓
4. §7 공통 자가점검 + 그 문서의 「받은 뒤 확인할 것」 → 수정 루프
```

**게이트에서는 반드시 멈춘다.** 후보를 제시하고 바로 만들기 시작하지 않는다.

## 1. 관계 구조 판별 (심장)

| 관계 | 신호 | 원시동작 | 슬라이드 예 |
|---|---|---|---|
| **순서** — 같은 형식이 차례로 | 연도·번호·단계가 있다 | **① 창 + 스트립** | 연표, 로드맵, 카운트 |
| **병렬 중 하나 강조** — 동급 N개 | 항목이 대등하고 N개다 | **② 요소 A→B** | 인물 소개, 요금제, 메뉴판 |
| **포함** — 전체 ↔ 부분 | 안으로 들어가거나 밖으로 나온다 | **③ 카메라** | 지도, 조직도, 목업, **표지→본문** |

### 판별 질문 셋

1. 항목의 개수가 정해져 있고 **순서가 의미를 갖는가** → ①
2. 항목들이 **대등하고, 한 번에 하나만** 보면 되는가 → ②
3. 한 항목 **안으로 들어가거나** 전체에서 부분으로 좁히는가 → ③

### 불릿 목록이면 — 모션이 아니라 내용을 고친다

불릿은 관계가 아니라 나열이라서 모션을 넣을 자리가 없다. 셋 중 하나로 다시 쓴다.
재구성안을 **글로 먼저 보여주고 승인을 받는다**(게이트 ②). 내용이 바뀌는 결정이다.

## 2. 후보 제시 → ★게이트 ①

관계에 맞는 패턴 2~3개를 골라, 각각 **무엇이 움직이나 / 어떤 인상인가 / 왜 이 슬라이드에
맞나** 를 한 문장씩만 쓴다. 그리고 **"어느 쪽으로 할까요?" 로 끝내고 멈춘다.**

**근거가 약한 패턴은 고를 때 그 사실을 같이 말한다.**

- ⚠️ **⑤「사진이 쏙」은 먼저 추천하지 않는다.** 실측이 없고 재현에 실패한 패턴이다
- ⚠️ **⑥「텍스트 녹아웃 줌」은 추천해도 되지만, 시간·이징이 빌린 값이고 아직
  끝까지 재현해 본 적이 없다는 걸 밝힌다.** 기하와 메커니즘은 검증돼 있다

### 사람이 여러 개를 고르면

**기본은 패턴당 하나씩 따로 만든다.** 패턴마다 조작 키와 상태 모델이 다르고, 하나가
깨졌을 때 나머지를 건드리지 않고 고칠 수 있어야 한다. **한 번에 다 만들지 말고
하나씩 만들어 확인받고 다음으로 간다** — 첫 개에서 잡은 디자인 결정이 나머지에 그대로
간다.

**"한 덱으로 이어서 보고 싶다"** 고 하면 그때 껍데기를 따로 만들어 각각을 장으로 넣는다.
그건 §5.1 의 키 분배 문제이므로 거기 규칙을 따른다. **묻지 않고 합치지 마라.**

## 3. 공통 상수 — 모든 패턴에 적용

### 이징

```
cubic-bezier(0.25, 0.1, 0.35, 0.95)
```

**오도미터 22점 + 하이라이팅 51점 = 합동 73점 최소제곱 피팅.**

| 곡선 | RMSE(합산) | |
|---|---|---|
| **★ 공통 최적** | **0.0330** | 채택 |
| `ease` | 0.0635 | reveal.js 기본값 |
| `ease-out` | 0.0563 | |
| `linear` | 0.1647 | |
| `ease-in-out` | 0.1668 | 최악 |

**이 곡선의 실제 거동 — 앞무게(front-loaded) 비대칭이다.**

- 초기 기울기 `y1/x1 = 0.40` → **linear 보다 느리게 출발한다**
- **1/4 지점(x≈0.244)에서 linear 의 1.9배 속도로 피크**에 도달한 뒤,
  **나머지 3/4 시간을 감속에 쓴다**
- 진행률: `x=0.10 → 0.084` · `x=0.50 → 0.732` · `x=0.69 → 0.90`

> `ease-in-out` 이 안 맞는 이유는 **대칭이기 때문**이고,
> `linear` 가 안 맞는 이유는 **이 앞무게 자체가 없기 때문**이다.
> "부드럽게 시작한다"는 통념 자체는 맞다. 실측이 뒤집은 건 **대칭성**이다.

### 전환 시간에는 공통 상수가 없다

**0.30 / 0.37 / 0.71 / 0.96초** — 패턴마다 다르다. **움직이는 거리가 멀수록 길다.**
「모핑은 0.5초」 같은 값을 쓰지 마라.

> ★ **눈으로 잰 시간은 물리 시간보다 짧다.** 위 곡선은 **69% 지점에서 이미 진행률 90%**
> 를 지난다 — 그때 「도착했다」고 보인다. 남은 10% 가 나머지 31% 시간에 걸쳐 안착한다.
> **그 안착이 무게감을 만든다. 길어 보인다고 줄이지 마라.**

## 4.1 패턴 문서를 못 읽으면 — 여기서 멈춘다

`references/` 를 읽을 수 없는 환경일 수 있다(붙여넣기로 쓰는 경우, 파일 접근이 없는
호스트 등). **그때 값을 임의로 배정하는 것이 이 스킬이 실제로 실패한 방식이다.**

**절차 — 이 순서를 지킨다.**

1. **아래 표의 시간은 그대로 써도 된다.** 여기 적힌 값이 곧 실측값이다.
2. **기하는 지어내지 마라.** 「문서 없이 못 하는 것」 칸이 비어 있지 않으면,
   **만들기 전에 사용자에게 문서를 달라고 요청한다** —
   릴리스의 `slide-motion-full.md` 한 장에 패턴 문서 6개가 다 들어 있다.
   ★ 스킬로 설치해 쓰는 중이라면 **코드 실행(code execution)이 켜져 있는지 확인해
   달라고 함께 말한다.** 꺼져 있으면 번들된 `references/` 를 읽지 못한다.
3. 사용자가 그래도 진행하라고 하면 만든다. 단 **네가 정한 값이라고
   설명과 코드 주석 양쪽에 밝힌다.** 실측이라고 부르지 마라.

### 최소 요약 — 문서가 없을 때의 마지노선

| # | 전환 시간 | 문서 없이도 아는 것 | 문서 없으면 못 하는 것 |
|---|---|---|---|
| ① 오도미터 | 숫자 롤 **960** · 나가는 이미지 **480** · 캡션 페이드 **~260**(추정) · 유지 **750** | 항상 앞으로만 굴린다 `(target-cur+10)%10` · 네 자리 **동시 출발·동시 도착** · 들어오는 이미지는 안 움직인다 | 없음 — 이 표로 거의 다 된다 |
| ② 하이라이팅 | 전환 **380** · 균등 유지 **450** · 강조 유지 **1200** · 본문 페이드 240(지연 120) | 반드시 **균등 상태를 경유** · 간격 **105→33** · 바닥 정렬 · 높이 427→**773** | 카드 폭 → **아래 공식으로 푼다** |
| ③ 그리드→히어로 | 히어로 **300** · 자리 교환 **367** · 나머지 페이드아웃 **200** | Grid 금지, `absolute` + px 전환 | **격자 좌표 20여 개** |
| ④ 줌스루 | 전환 **709** | 다음 장은 확대되지 않는다 · `transform-origin` = 들어갈 지점 | ★ **14행 회전·배율 키프레임 표. 대체 불가 — 반드시 문서를 받아라** |
| ⑤ 사진이 쏙 | **500**(빌림) | 시작·끝 상자의 **가로세로 비를 맞춰라** | 편집화면 판독 좌표 4벌 |
| ⑥ 텍스트 녹아웃 | **900**(빌림) | 글자 대문자 높이 = **슬라이드 높이 × 0.329** · 확대 배율은 상수가 아니라 **이분탐색** · 원점은 뚫린 획 위 | 없음 — 이 표 + §6 함정으로 된다 |

### ② 카드 폭 — N 개로 일반화

실측은 **3개·한 줄**뿐이다. N 이 다르면 아래로 푼다. **이 공식은 실측이 아니라
실측값(N=3)을 재현하는 일반화다** — 그 사실을 주석에 남긴다.

```
카드 영역 폭 W = 1747      (1920 무대, 좌우 여백 ≈86)
균등:  card  = (W − 105×(N−1)) / N            gap 105
강조:  small = (W −  33×(N−1)) / (N + 3)      gap 33
       hero  = 4 × small                      (실측 폭비 1119:281 ≈ 4:1)
```

N=3 검산: `card 512.3` · `small 280.2` · `hero 1120.7` — 실측 512 / 281 / 1119 과 일치.
N=4 → `card 358` · `small 235` · `hero 942`.

> **N 은 3~5 까지다.** 축소 카드가 200px 아래로 내려가면 한 줄에 세우지 말고
> **패턴 ③(격자)** 으로 간다. 높이(427 / 강조 773)와 간격은 N 과 무관하다.

## 5. 공통 규격 — 어떤 패턴이든 이대로 만든다

### 불변 — 환경이 어디든 이건 지킨다

- **1920×1080 고정 무대**를 만들고, **무대 전체에만** `transform: scale()` 을 걸어
  화면에 맞춘다(레터박스, `ResizeObserver` 로 갱신).
  브라우저 확대 100% 에서도 잘리지 않아야 한다
- ★ **조작은 사람이 한다.** 클릭 / ← → / Space / Esc 로만 움직인다
  - 열었을 때 아무것도 저절로 움직이지 않는다. 첫 화면은 정지 상태다
  - **타이머로 화면을 진행시키지 마라** (`setInterval`·연쇄 `setTimeout` 로 다음 장·다음
    스텝으로 넘어가는 코드 금지)
  - ★ **전환 잠금 해제는 이 금지의 대상이 아니다.** 「사람 조작 없이 화면이 진행되는
    것」이 금지지, 시계를 보는 것 자체가 금지가 아니다. 다만 **잠금은 시간이 아니라
    사건으로 푸는 게 낫다** — `transitionend` / `animation.finished` 를 쓰고,
    그게 안 오는 경우까지 막으려면 `performance.now()` 비교로 판단한다.
    **`setTimeout` 으로 플래그를 되돌리는 방식은 전환이 끊겼을 때 영구 잠금이 된다**
  - 자동재생을 굳이 넣겠다면 **기본값은 꺼짐**이고, 사람이 켜야만 돈다
- 전환 중에는 입력을 무시한다. 상태는 절대 인덱스로 들고 양방향으로 설계한다
- `prefers-reduced-motion: reduce` 대응 (전 duration 0)
- 모션 상수는 파일 맨 위에 모으고 출처(실측/보간/추정/빌림/연출)를 주석으로 밝힌다

### 위임 — 형식은 호스트 규칙이 이긴다

**파일 형식·파일명·전달 방법은 이 문서가 정하지 않는다.** 실행되는 환경에 규칙이
있으면 **그쪽을 따른다** — 아티팩트가 강제인 곳이면 아티팩트로, 특정 컴포넌트로만
내보내야 하는 프로젝트면 그 컴포넌트로 낸다. **위 「불변」만 그 안에서 지키면 된다.**

호스트에 아무 규칙이 없을 때의 기본값은 **단일 HTML 파일 하나**,
파일명 `slide-motion-<주제>.html`, 외부 의존은 웹폰트까지만.

어느 쪽이든 **채팅 본문에 전체 코드를 다시 붙여넣지 않는다.** 무엇을 만들었고
어디를 확인하면 되는지만 3~5줄로 말한다.

### 디자인은 사용자 것이다 — 레퍼런스를 흉내내지 않는다

카탈로그가 주는 것은 **좌표와 시간뿐**이다. 색·글꼴·주제는 하나도 지정하지 않았다.

- ★ **디자인 시스템이 이미 붙어 있으면 그쪽이 우선이다.** 프로젝트에 토큰·컴포넌트·
  브랜드 규정이 있으면 그걸 쓴다. 아래는 **그런 게 없을 때의 기본값**이다
- 주제·카피·사진·타이포·색은 **전부 새로 고른다**. 정한 이유를 주석 한 줄씩 남긴다
- 폰트는 **역할 3종**으로 나눠 고른다 — (가) 큰 숫자/헤드라인 (나) 국문 본문 (다) 모노 라벨
- **이미지는 플레이스홀더로 두지 말고 실제 사진을 쓴다**(Unsplash 등).
  ★ **다만 외부 이미지는 차단될 수 있다.** `onerror` 로 폴백을 반드시 넣어라 —
  **CSS 그라디언트나 인라인 SVG**로 대체하고 레이아웃은 그대로 유지한다.
  빈 칸이 남으면 안 된다

## 5.1 이미 있는 덱에 넣을 때

실제 요청은 대개 **새 슬라이드 한 장이 아니라 이미 있는 덱**이다. 먼저 원본 덱이
무엇으로 만들어졌는지 확인한다.

**원본이 PPT·구글슬라이드 등 웹이 아니면** — 덱을 옮기려 하지 마라.
**모션 장만 별도 HTML 로 만들고, 발표 중 그 대목에서 열어 보여주는 것**이 기본이다.
덱 전체를 HTML 로 이전하는 건 이 스킬의 범위 밖이고, 물어보지 않고 시작하면 안 된다.

**원본이 HTML 덱이면** — 그 덱의 런너 규약을 먼저 읽고 키를 나눈다.
이걸 안 하면 `←` `→` 가 슬라이드 이동과 인슬라이드 스텝에 동시에 걸려 둘 다 망가진다.

- **`←` `→` 는 덱의 것이다** — 장 이동에 그대로 둔다
- **인슬라이드 스텝은 `Space`(전진) / `Shift+Space`(후진)** 로 옮긴다
- ★ **스텝이 남아 있는 동안만 `→` 를 가로채고, 다 쓰면 흘려보낸다**
  (`stopPropagation` 을 조건부로 건다). reveal.js 의 fragment 와 같은 규약이라
  발표자가 배울 게 없다
- **뒤로 갈 때도 대칭이어야 한다** — 앞 장에서 `←` 로 돌아오면 그 슬라이드는
  **마지막 스텝 상태**로 복원된다. 첫 스텝으로 리셋되면 되감기가 끊긴다
- 무대 스케일이 덱의 것과 겹치면 **이중 스케일**이 된다. 덱이 이미 무대를 맞추고
  있으면 §5 의 무대 스케일은 넣지 말고 덱의 좌표계를 그대로 쓴다

**원본 덱을 고칠지 따로 뺄지는 사람이 정한다.** 파일이 하나뿐인 덱이면 사본을 만들고,
사본에서 작업했다는 걸 말한다.

## 6. 함정 — 카탈로그 전체에 적용

- ★★ **「2단계 커밋」 — transition 을 붙이는 것과 값을 바꾸는 것을 같은 프레임에 하지 마라.**
  스타일이 플러시되지 않아 **전환이 아예 안 걸리고 요소가 순간이동한다**
  (`getAnimations()` 가 0을 돌려준다).
  → transition 을 붙인 뒤 **강제 리플로우(`el.offsetHeight`)** 하거나
  **`requestAnimationFrame` 으로 다음 프레임에** 값을 바꾼다.
  ★ 이게 **「동시 출발」을 조용히 깨뜨린다** — 한쪽은 굴러가는데 다른 쪽만 텔레포트하는데
  눈으로는 "빠르네" 정도로 보여 놓치기 쉽다
- ★ **기능 이름만 적으면 기본값은 모델이 정한다.** 원하는 기본 상태는 **문장으로** 적는다
- ★ **"부드럽게"는 지시가 아니다.** **대상 / A→B / 시간 / 이징 / 순서 다섯 칸**을 다 채운다
- ★ **모핑되는 요소는 슬라이드를 나누지 않는다.** 같은 DOM 노드를 유지하고 상태만 교체한다
- ★ **「카메라」 계열(③⑥)의 `transform-origin` 은 「들어갈 지점」이다.**
  슬라이드 중앙이 아니라 **실제로 통과해 들어갈 곳**에 둔다. 그리고 그 점이
  **정말 통과 가능한 곳인지** 확인해라 — 막힌 곳(⑥의 글자 counter 같은)이면 영원히 안 열린다.
  검증법은 공통이다: **제대로 잡혔으면 전환 내내 원점의 화면 좌표가 움직이지 않는다**
- ★ **폰트·글꼴에 따라 값이 달라지는 수치는 상수로 못 박지 마라.**
  디자인은 자유 영역이라 **모델이 반드시 다른 폰트를 고른다.** 그때 깨질 값이면
  **푸는 방법을 주고 매번 풀게 한다** (⑥의 확대 배율이 그 사례다)
- ★ **`var()` 에서 파생된 속성은 그 속성에도 transition 을 따로 걸어야 한다.**
  등록되지 않은 커스텀 속성은 그 자체가 보간되지 않는다
- **`transform`·`opacity` 가 기본이지만 조건부 규칙이다** — 레이아웃 자체가 변하는 효과에는
  `grid-template-columns`(②)나 절대 위치 px 전환(③④⑤)이 정답이다.
  `font-size` 전환도 **절대 위치 요소 내부라면 안전**하다
- ⚠️ **개별 요소를 `transform: scale()` 로 키우지 마라** — 안의 글자·사진이 찌그러진다.
  **단, 1920×1080 무대 전체를 화면에 맞추는 스케일은 예외다**(§5).
  그건 뷰포트 맞춤이지 요소 확대가 아니다
- **PDF·이미지로 내보내면 모션은 전멸한다.** 배포본은 정지 상태 기준으로 따로 설계한다
- **모핑 남용 금지.** 도입부 1회 + 핵심 전환 1~2회가 상한선이다

## 7. 수정 루프 — 증상에서 원인으로

### 공통 자가점검 — 패턴 문서와 무관하게 매번 돌린다

패턴별 확인 목록은 각 문서 맨 끝에 있다. **아래 여덟은 문서 없이도 돌릴 수 있다.**

1. ★ **전환이 실제로 걸렸는가** — 전환을 시작시킨 직후
   `document.getAnimations().length` 가 **0 이 아니어야** 한다.
   0 이면 값이 바뀌긴 했는데 애니메이션 없이 점프한 것이다(§6 「2단계 커밋」)
2. 열자마자 **아무것도 저절로 움직이지 않는가**
3. 끝까지 갔다가 되돌아왔을 때 **첫 상태와 같은가** (양방향 대칭)
4. 전환 도중 키를 **연타해도** 상태가 어긋나지 않는가.
   그리고 **연타 뒤에도 계속 조작이 되는가** (영구 잠금이면 §5 의 잠금 해제 문제다)
5. 브라우저 확대 **100% 에서 무대가 잘리지 않는가**
6. `prefers-reduced-motion: reduce` 를 켠 채로 열면 **즉시 최종 상태**로 가는가
7. 외부 이미지를 차단해도 **빈 칸이 남지 않는가**
8. 파일 맨 위 상수마다 **출처 주석**(실측/보간/추정/빌림/연출)이 붙어 있는가

| 증상 | 원인 | 고칠 곳 |
|---|---|---|
| 열자마자 저절로 움직인다 | 타이머가 들어갔다 | §5 |
| 툭 튀고 전환이 없다 | Grid 애니메이션 불가 / 플러시 누락 | ③ · §6 |
| 한쪽만 순간이동한다 | **2단계 커밋 누락** | §6 |
| 글자가 납작해졌다 | `scaleX` 로 폭을 흉내냈다 | ② |
| 안의 내용이 찌그러진다 | 요소를 `scale` 로 키웠다 / 상자 비가 다르다 | ③⑤ |
| 글자만 툭 점프한다 | `var()` 파생 속성에 transition 안 걸었다 | §6 |
| 대상이 옆으로 흘러 나간다 | `transform-origin` 이 슬라이드 중앙 | ④⑥ |
| 화면이 아예 안 열린다 | 원점이 막힌 곳(글자 counter) | ⑥ |
| 끝났는데 구석에 검정이 남는다 | 확대 배율을 상수로 박았다 | ⑥ |
| 이징이 미묘하게 어긋난다 | 트랙이 `fr` 이다 | ② |
| 되감기에서 숫자가 거꾸로 흐른다 | 리셋에 `transition:none` 이 없다 | ① |
| 이미지 자리가 비었다 | 외부 이미지 차단 + 폴백 없음 | §5 |
| 레퍼런스랑 똑같이 생겼다 | 디자인 자유 영역을 안 열었다 | §5 |
| 한 번 전환한 뒤 조작이 안 먹는다 | 잠금 플래그가 안 풀렸다 (`setTimeout` 의존) | §5 |
| `→` 를 누르면 장이 넘어가 버린다 | 덱 런너와 키가 겹쳤다 | §5.1 |
| 슬라이드가 화면에서 작아졌다 | 무대 스케일이 덱의 것과 이중으로 걸렸다 | §5.1 |
| 되감으니 앞 장이 첫 스텝으로 리셋된다 | 스텝 상태를 장별로 안 들고 있다 | §5.1 |

**증상이 표에 없으면 추측하지 말고 무엇이 어떻게 보이는지 되묻는다.**
